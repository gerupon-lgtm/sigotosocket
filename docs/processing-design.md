# 処理設計 — シゴトソケット

判定はすべてルールベース。**LLMに判断させない。**

## 1. 採点（F-003）

```
raw[s] = mean( answers[i] for i in items(s) )        # 1.00〜5.00
```

- 未回答が1件でもあれば結果へ進めない（F-001の入力チェック）
- 丸めは表示時のみ。内部は倍精度のまま扱う

## 2. 個人内標準化（F-003・決めごとA-1）

```
m  = mean( raw[s] for s in 8尺度 )
sd = sqrt( mean( (raw[s] - m)^2 for s in 8尺度 ) )   # 母集団標準偏差（÷8）
z[s] = (raw[s] - m) / sd
```

- **母集団標準偏差（÷n）を使う。標本標準偏差（÷n-1）に変えない**
- `sd == 0`（全尺度が同値）のとき、z を計算せず `standardizable = false` とし、専用メッセージを表示する。**ゼロ除算を発生させない**
- 浮動小数の誤差で `sd` が極小になる場合に備え、`sd < 1e-9` を判定不能として扱う
- ビッグファイブ側も同じ式で5因子内標準化する（第2フェーズ）

## 3. 順位付け

```
rank = 8尺度を z の降順で並べたもの
```

- z が同値の場合は**正準順で安定ソート**する。実行ごとに順位が変わってはならない

## 4. タイプ判定（F-004）

```
typeId = type-<正準順で並べた rank[0], rank[1]>
```

**僅差の扱い**（決めごとなし・閾値は【想定】0.15）:

```
if |z[rank[1]] - z[rank[2]]| < THRESHOLD:
    alternativeTypeId = type-<正準順で並べた rank[0], rank[2]>
```

- 2つのタイプ名を「どちらとも読めます」として並べて提示する。1つに断定しない
- rank[0] と rank[1] が僅差でも `typeId` は変わらない（順序なしのため）。**この性質のおかげで1位・2位の入れ替わりに強い**
- `standardizable == false` のときは判定せず、`primaryTypeId = null`

## 5. カードの絵柄決定（F-019）

```
pose = character-pose-<rank[0]>      # 1位尺度でポーズが決まる
prop = prop-<rank[1]>                # 2位尺度で小物が決まる
```

- タイプ名は28通り、絵柄は順序を反映して56通りの見え方になる（`docs/data-model.md` §5）
- `standardizable == false` のときは専用の中立ポーズ `character-pose-neutral.webp` を使う
- 連携前後でむっくんと小物の画像サイズは変えない。連携時だけ猫を加え、実体矩形で3点の左右端を求める
- 連携時は猫をむっくん実体高の75%、間隔2px、接地線+50pxで置き、3点セット全体をカード中央から右へ34px移す
- 結果画面は固定34pxではなく、カード幅に対する比率 `34 / 1080` で同じ左右位置へ追従する

## 5-1. 共有テキスト（F-018）

`composeShareResultText()` はS-003と同じ確定済みの結果モデルから、称号・説明・ホランド型・連携結果・8尺度の点数・免責を組み立てる。
生回答、連携コード、URLは含めない。Web Shareが使えない場合も、この文字列をClipboardへ渡す。

## 5-2. 連携受領後の分岐（F-010・F-011）

正常な結果コードを受け取ったら、既存の `bigFive` の有無で「受領／更新」、最新のORVIS結果の有無で次の操作を決める。

| 既存の連携 | 最新のORVIS結果 | 表示と処理 |
|---|---|---|
| なし | なし | 「受け取りました」。連携を保存し、45問の開始または途中回答の再開へ |
| あり | なし | 「更新しました」。単一スロットを置き換え、45問の開始または再開へ |
| なし | あり | 「受け取りました」。最新結果へ付け、組み合わせた結果へ |
| あり | あり | 「更新しました」。最新結果の連携だけを置き換え、組み合わせた結果へ |

不正コードではこの分岐を起こさない。正常受領後の案内は画面状態であり、採点・タイプ判定・保存済み結果の作成日時を変更しない。

## 5-3. ココロパレアへの入口（F-010）

通常の姉妹アプリ紹介はココロパレアのトップURLへ遷移する。トップと未連携結果の「連携方法」から進む場合だけ `#/sigotosocket` を付けた専用入口へ同じタブで遷移し、ココロパレア側で50問詳細履歴の有無に応じた分岐を行う。

## 6. 結果文の組み立て（F-006）

アプリ側で**そのまま表示できる完成文**まで作る。

1. タイプ名と説明（命名表から取得）
2. 上位2尺度の解説（尺度定義から取得）
3. 下位1尺度の解説（「相対的に低い」とのみ書く。**「苦手」「向いていない」と書かない**）
4. 判定不能時は専用文

**禁止**: 「平均より高い」「人より〜」「〇〇な人は少数派」等、集団比較を含む表現（決めごとB-1）。文言テンプレートの単体テストで、禁止語の混入を検出する。

## 7. LLM推敲（F-007・不採用）

T-031で実装しないと決定した。結果文はF-006のルールベース出力をそのまま使い、LLMへ回答・得点・結果文を送信しない。`appMeta.llmEndpoint` は `null` のままとする。

## 8. 整合／不整合の判定（F-012・第2フェーズ・決めごとB-2）

対象は次の6ペアのみ。

| Big5因子 | ORVIS尺度 | 参照相関（符号と大小のみ使用） |
|---|---|---|
| intellectImagination | creativity | .30 |
| intellectImagination | erudition | .34 |
| intellectImagination | leadership | .29 |
| agreeableness | altruism | .42 |
| extraversion | leadership | .38 |
| conscientiousness | organization | .20 |

**参照相関を係数として掛けない。**ペアを選ぶ根拠と、本文に添える但し書きにのみ使う。

### 8-1. 出す形（2026-09-05 確定・要件定義書 v1.21）

**並置型を採る。**「特性からはこう予想されるが、実際は違った」とは書かない。本人の2つの事実と、原典で報告された結びつきの強さを**別々に**書き、両者を結ぶ推論は読み手に返す。

この形を採る理由は §10-2 にある。翻訳後の項目で相関が再現するかを確かめる友人サンプルが無く、当面そろう見込みも無い。並置型なら、翻訳で構成概念が崩れていても**文が偽にならない**（原典の r は原典の事実、本人の z は本人の事実であり、どちらも翻訳の成否に依存しない）。

### 8-2. 選び方

対象外にするもの。

- 未連携、ORVIS側が判定不能（`standardizable === false`）、5因子が全部同値（`z` が null）のいずれかなら、節ごと出さない
- ペアの**いずれかの `|z|` が 0.3 未満**のものは落とす。本人の中で真ん中あたりのものについて、向きの話をしない

向きと強さ。

| 向き | 判定 | 強さ |
|---|---|---|
| 揃った | 2つの `z` が同符号 | `min(|z_factor|, |z_scale|)` |
| 分かれた | 異符号 | `|gap|`（`gap = z_orvis[scale] - z_bigfive[factor]`） |

**強さは順番を決めるための目安であって、指標ではない。**2つの測り方は厳密には同じ量ではない。値そのものを画面に出さない。

§8 が `|gap|` 一本だったのを2種類に分けたのは、並置型では「揃った」も「分かれた」と同じ重さで扱うためである。`|gap|` だけだと、両方はっきり高い人（＝いちばん語る価値のある一致）が `gap ≈ 0` で最下位に沈む。

並べ方。

- 強さの降順。同値なら §8 冒頭の表の並び順（実行ごとに変わらない）
- 上から採り、**同じ因子・同じ尺度は1回まで**。`intellectImagination` は3ペア、`leadership` は2ペアに出てくるので、これが無いと同じ話が並ぶ
- **最大2件**

### 8-3. 文言の型

共通の但し書きは**節の前書きに1回だけ**置き、各件から外す。各件を3段落にすると画面が文章で埋まる。

前書き（全員同じ）:

> ココロパレアの5因子と、45問の8領域を並べています。ORVISの原典では、下に挙げた組み合わせに結びつきが報告されています。ただしその数値は英語の原版のもので、日本語にした45問で同じ強さが出るかは、まだ確かめていません。読み方が当てはまるかどうかは、あなたが決めてください。

**この2文が §10-2 の検証ゲートの置き換えである。**削らない。

各件は2段落。

| 段落 | 中身 | 決まり方 |
|---|---|---|
| 1 | 本人の2つの事実＋原典での強さ | ルールベース。差し込むのは位置づけ2つ・接続1つ・r 1つだけ |
| 2 | 読み方 | 定型文（`domain/cross-analysis-text.js`）。LLMは使わない（決めごとB-5） |

位置づけの語は、本人の中の順位で決める。5因子で1位なら「いちばん高く」、5位なら「いちばん低く」、それ以外は「高いほう／低いほう」。8領域も同じ規則。**個人内比較しか書かない**（決めごとB-1）。

向きが揃っていて位置づけの語まで一致するときは、**2文目を言い換える**（`echoPhrase`）。「いちばん高く出ています」が2回続くと単調に読める（2026-09-05 本人指摘）。言い換えるだけで意味は変えない。

定型文は**1ペアにつき3本、計18本**。「揃った」は両方高いのと両方低いので別の文がいる（同じ文では意味が通らない）。「分かれた」は左右対称なので1本でよい。

禁則（テストで機械的に検証する）:

- 18本すべてが断定を避ける語で終わる（かもしれません／ようです／と読めます／という読み方ができます）
- 「平均より」「人より」「一般に」を含めない（決めごとB-1）
- 「べき」「向いています」「適職」を含めない（職業を断定しない）

### 8-4. 該当が無いとき

6ペアすべてが落ちたときは、次の1件を出す。**これも正式な結果**（決めごとB-3）。

> 6つの組み合わせのどれについても、あなたの中ではっきりした向きが出ませんでした。これも結果のひとつです。

一様乱数20万人の粗いモデル【想定】では、②が0件になるのは 0.6%、1件以上出るのは 99.4%。③のみだった現状の 42.3% から広がる。このモデルはORVISとBig5を独立に引いているので、「揃った」の比率は実際より低く出る。

## 9. 固有性の判定（F-013・第2フェーズ）

- 対象は Big5 との相関がほぼゼロの尺度（`production`・`adventure`）
- `z` が上位に入っている場合、「性格特性からは予測できない、あなた固有の興味」として提示する
- 根拠は「予測できないこと自体が事実である」点。①②より説明の確度は高い

## 10. 検証（実装前・実装後）

### 10-1. 合成プロフィールの端値テスト（必須）

| ケース | 期待 |
|---|---|
| 全項目1 | `standardizable = false`、専用メッセージ、例外を投げない |
| 全項目5 | 同上 |
| 全尺度の平均が完全一致 | 同上 |
| 1尺度だけ突出 | 1位が確定し、2位以下が僅差なら代替タイプが出る |
| 2位と3位が完全同値 | `alternativeTypeId` が設定される |
| 1位と2位が完全同値 | `typeId` が変わらない（順序なしの性質） |
| 未回答が1件 | 結果へ進めない |
| 浮動小数で sd が極小 | 判定不能として扱う |

### 10-2. 友人サンプル（n=10〜20）での符号確認

翻訳後の項目で、§8の主要な相関（agreeableness↔altruism、intellectImagination↔creativity/erudition、extraversion↔leadership）の**符号が再現するか**を確認する。値の一致は求めない。

**このゲートの置き方を変えた（2026-09-05・要件定義書 v1.21）。**

| | 旧 | 新 |
|---|---|---|
| ゲートの対象 | ②を出すか出さないか | **言い切りの強さ** |
| 再現しない場合 | ②層を落とし、①③のみで提供する | ②は出す。§8-3 の並置型の文言に固定する |
| 再現した場合 | ②を残差型で出す | 残差型（「特性からは予想されるが実際は違った」）へ**格上げしてよい** |

**理由。**個人開発でサンプル数を確約できず、旧のゲートは開かない見込みが高い。開かないままだと「保留」が実質の不採用になり、連携した人の 57.7% が文章を1件も読めない状態が続く（§8-4）。並置型は原典の r と本人の z を別々に書くので、翻訳で構成概念が崩れていても文が偽にならない。**検証は「出すかどうか」ではなく「どこまで言い切るか」を決めるものとして残す。**

### 10-3. 短縮後のα実測

同サンプルから各尺度のCronbachのαを算出するスクリプトを用意する（`scripts/items/alpha.mjs`）。推定値（全尺度.72以上）と比較する。

**実装済み（2026-09-05・T-035）。**

```
npm run sample:template friends.csv   # 見出し行だけのCSVを作る
npm run sample:check friends.csv      # αと6ペアの符号を出す
```

- 1行1人。`respondentId` は好きな識別子（**本名を入れない**）
- 5因子の列は 1.00〜5.00 の内部平均。**空でもよい**（その行はαにだけ使う）。1つでも欠けた行はペアに数えない（ペアごとに n が変わるのを防ぐため）
- 45項目は 1〜5 で埋める。値域外・欠損の行は落とし、理由を出す。他の行は活かす
- **判断はスクリプトがしない。**n と但し書きを必ず添えて出し、②を出すか落とすかは人が決める
- 手仕事・挑戦のαが低いときは名指しで知らせる（③層が依拠するため。要件定義書 §6-7）
