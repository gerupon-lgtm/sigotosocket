# 連携仕様 — ココロパレア側に実装してもらうもの

**渡す相手：シゴトソケット（https://sigotosocket.sikumilab.com/）**
作成 2026-09-05。対応する機能IDは F-010（受け取り）／F-023（ココロパレア側の遷移）、タスクは T-032。

この文書は**ココロパレアの担当者へ渡すため**に書いている。
シゴトソケット側の受け取りは実装済みで本番稼働しており、**あちらに必要なのはコードを作って遷移するボタン1つ**である。

**判断を仰ぐ項目は残していない。**置き場所・文言・遷移の仕方・対象とする結果は §6 ですべて決めてある。
仕様に疑問があれば実装前に確認してほしい。**推測で埋めないこと。**

## 0. この文書の読み方

節ごとに根拠の強さが違う。**推測を確定として書かないため**、次の印を付ける。

| 印 | 意味 |

## 1. 受け渡しの形

**【確定】** URLのフラグメント（`#` 以降）で渡す。

```
https://sigotosocket.sikumilab.com/#b5=v1-342288401195267
```

**フラグメントを使う理由**：`#` 以降はHTTPリクエストに含まれないため、通信経路にもサーバーのアクセスログにも得点が残らない。クエリ文字列（`?b5=`）では残るので使わない。

**【確定】** シゴトソケットは受け取り後、成否にかかわらず `history.replaceState` でフラグメントを消し、URLを `#/start` にする。得点入りのURLがそのまま共有されるのを防ぐため。

## 2. 結果コードの仕様

### 2-1. 全体の形

**【確定】**

```
v1-CCCCCCCCCCCCCCC
   └─ 3桁 × 5因子 = 15桁の半角数字
```

- 先頭は版数 `v1` と区切りのハイフン
- 本体は**ちょうど15桁の半角数字**。区切り文字を入れない

### 2-2. 因子の並び

**【確定】** この順で連結する。**並べ替えない。**

| # | factorId | 日本語 |
|---|---|---|
| 1 | `intellectImagination` | 知性・想像力 |
| 2 | `conscientiousness` | 勤勉性 |
| 3 | `extraversion` | 外向性 |
| 4 | `agreeableness` | 協調性 |
| 5 | `emotionalStability` | 情緒安定性 |

**【確認済み】** この並びは、ココロパレアの `app/js/config/factor-order.js` の `FactorOrderDefinition.factorIds` と同じ順序である（`codex/big-five-q006` ブランチを読んで確認）。あちらの定数をそのまま使えば一致する。

### 2-3. 各因子の値

**【確定】** 各因子の**内部平均（1.00〜5.00）を小数第2位で四捨五入して100倍**し、**3桁ゼロ埋め**。

```
100 = 平均 1.00（下限）
500 = 平均 5.00（上限）
```

**【確認済み】** ココロパレアの `rawMean`（`app/js/domain/factor-result.js` の `FACTOR_RESULT_FIELDS` に含まれる）がこの内部平均にあたる。`rawMean = keyedSum / itemCount` で、回答は1〜5なので値域は 1〜5。

**精度について【確認済み】**：50問なら1因子10項目なので `rawMean` は 0.1 刻み、20問なら4項目なので 0.25 刻み。**どちらも ×100 して整数になるため、丸めによる情報の欠落は起きない。**

### 2-4. 例

| 因子 | 内部平均 | 3桁 |
|---|---|---|
| intellectImagination | 3.42 | `342` |
| conscientiousness | 2.88 | `288` |
| extraversion | 4.01 | `401` |
| agreeableness | 1.95 | `195` |
| emotionalStability | 2.67 | `267` |

→ `v1-342288401195267`

## 3. コード生成の手順

**【確定】** シゴトソケット側の検証を通すには、次と同じ結果になればよい（実装の書き方は問わない）。

```js
// factors: ココロパレアの resultModel.factors（factorId と rawMean を持つ配列）
const FACTOR_ORDER = [
  "intellectImagination", "conscientiousness", "extraversion",
  "agreeableness", "emotionalStability",
];

function buildLinkCode(factors) {
  const body = FACTOR_ORDER.map((factorId) => {
    const factor = factors.find((f) => f.factorId === factorId);
    if (!factor) throw new Error(`因子がない: ${factorId}`);
    const hundreds = Math.round(factor.rawMean * 100);
    if (hundreds < 100 || hundreds > 500) throw new Error(`値域外: ${factorId}=${factor.rawMean}`);
    return String(hundreds).padStart(3, "0");
  }).join("");
  return `v1-${body}`;
}

// 呼ぶのは mode === "detail50" の結果だけ（§6-1）。同じタブで遷移する（§6-3）
function openSigotosocket(snapshot) {
  if (snapshot.mode !== "detail50") return;   // 20問プレビューからは渡さない
  location.href = `https://sigotosocket.sikumilab.com/#b5=${buildLinkCode(snapshot.resultModel.factors)}`;
}
```

**注意点**

- `Math.round` を使う。切り捨て（`Math.floor`）だと 2.999… が 299 になり、意図とずれる
- `padStart(3, "0")` を忘れない。1.00 は `100` なので3桁になるが、実装ミスで2桁になると全体の桁数が崩れて**まるごと無視される**
- 因子が1つでも欠けたらコードを作らない（**壊れたコードを渡さない**）

## 4. シゴトソケット側が弾く条件

**【確定】** 次のいずれかに当てはまると、**コードを無視して単体の結果を表示する**。利用者にエラーは見せない。

| 条件 | 例 |
|---|---|
| 版数が既知でない | `v2-...`、版数なしの `342288...` |
| 本体が15桁でない | 14桁、16桁 |
| 半角数字以外が混じる | `v1-34228840119526a`、全角数字 |
| 3桁のどれかが 100〜500 の外 | `099...`、`501...` |
| 空 | `#b5=`、`#b5=v1-` |

**エラーを見せない理由**：連携は上乗せの機能であり、他アプリのコードの不備でこちらの診断が止まる理由がないため。

**実装の場所**：`app/js/domain/big-five-link.js`（検証）、`app/js/infrastructure/linkage-intake.js`（受け取りと保存）。テストは `app/tests/big-five-link.test.js` と `app/tests/linkage-intake.test.js`。

## 5. 過去の結果から連携できるか

**【確認済み】できる。**

- ココロパレアは結果を履歴として保存しており（`progress-storage.js` の envelope に `results` 配列）、各結果の `resultModel.factors` に `rawMean` が残っている
- したがって、**履歴画面や過去の結果画面からでもコードを生成できる**。診断をやり直す必要はない

**ただし実行して確かめてはいない。** 実際に保存済みデータを読んで `rawMean` を取り出すところまでは検証していないので、実装時に1件で確認してほしい。

**シゴトソケット側の受け入れ【確定】**

- ORVISを**まだやっていない**人がコード付きで来た場合：連携を保存しておき、45問を終えた時点で結果に結び付ける
- ORVISを**すでに終えている**人がコード付きで来た場合：**再回答は発生しない。**既存の結果に後から結び付ける（結果IDも作成日時も変わらない）
- 結果が複数ある場合：**いちばん新しい結果**にだけ結び付ける

## 6. 決まったこと

**2026-09-05 に本人が決定。**ココロパレア側で判断する必要はない。

### 6-1. 連携できるのは「50問の詳細結果」だけ

**【確定】** 20問の簡易プレビュー（`mode: "preview20"`）からは連携させない。
ボタンを出すのは `mode: "detail50"` の結果に限る。

**理由。** いまシゴトソケットが出す③固有性は、**5因子の「値」を使っていない**
（`uniqueInterest()` は連携の有無しか見ず、判定はORVISの順位だけで決まる）。
その意味では20問でも表示は変わらない。

ただし**②整合／不整合を入れると5因子のz値を使う**ようになり、そこで
20問由来（1因子4項目）の粗い値が混ざる。**v1のコードは20問か50問かを持たない**ので、
後から選り分けられない。「まず50問だけ許し、あとで20問も許す」方向へはいつでも
広げられるが、逆は難しい。**狭い側から始める。**

### 6-2. ボタンは詳細結果の操作群に1つだけ

**【確定】** 置き場所は**50問の詳細結果画面**の操作群（`renderActions` にあたる並び）。
履歴画面と称号カード画面には置かない。導線が散ると、どこから渡せるのか分からなくなる。

**文言：「シゴトソケットへ結果を渡す」**

**過大な約束をしない。**§8のとおり、いま連携して増えるのは③固有性だけで、
上位2領域に手仕事・挑戦が入らない人には見た目の変化が出ない。
「適職が分かる」「天職が見つかる」のような文言は使わない
（シゴトソケットは職業を提示しない方針のため。要件定義書 §7-3）。

### 6-3. 同じタブで開く

**【確定】** `window.open` の別タブではなく、同じタブで遷移する（`location.href` など）。

スマホ主体でタブが溜まるのを避ける。シゴトソケットは受け取り後に
`history.replaceState` でURLを差し替えるので、**`#b5=` 付きの履歴が残らず、
ブラウザの戻るでココロパレアへ戻れる。**

### 6-4. 逆向きの導線は今回作らない

**【確定】** ORVISの結果をココロパレアへ渡す仕組みは、今回のスコープ外
（F-021・F-023 の範囲）。

シゴトソケット側からココロパレアへの**リンク**は実装済み（トップの説明パネル内）。
データの受け渡しは伴わない、ただの遷移である。

### 6-5. 称号IDは載せない

**【確定】** v1のコードは5因子だけを運ぶ（2026-09-05 本人決定）。
載せる場合は `v2` を新設する。シゴトソケット側は未知の版を無視するので、
古い版のまま放置しても壊れない。

### 6-6. 利用者への説明

**【確定】** ボタンの近くに、渡すものを一行で書く。

> 5つの数値だけを渡します。回答そのものは渡しません。

シゴトソケット側のトップにも同じ趣旨を書いてある（説明パネルの「ココロパレアと連携すると」）。

## 7. 動作確認の手順

**【確定】** シゴトソケット側は本番で動作を確認済み。次の手順で誰でも確かめられる。

1. ブラウザで `https://sigotosocket.sikumilab.com/#b5=v1-342288401195267` を開く
2. URLが `https://sigotosocket.sikumilab.com/#/start` に変わることを確認（フラグメントが消える）
3. 開発者ツールのコンソールで次を実行し、5因子が入っていることを確認

```js
JSON.parse(localStorage.getItem("sigotosocket:v1")).bigFive.factors
// → { intellectImagination: 3.42, conscientiousness: 2.88, extraversion: 4.01,
//     agreeableness: 1.95, emotionalStability: 2.67 }
```

4. 壊れたコードも試す（`#b5=v1-999999999999999` など）。**エラーが出ず、保存もされず、URLだけ消える**のが正しい挙動

**連携の効果を見るには**：45問に回答し、**手仕事か挑戦が上位2領域に入った場合**に「性格からは予測できない興味」が結果画面へ増える。カードにはゲストの猫が並ぶ。上位2領域がそれ以外だと、連携しても見た目の変化は起きない（②整合／不整合が未実装のため。§8参照）。

## 8. 連携しても今は増えないもの

**【確定】** 正直に書いておく。現時点で連携して増えるのは**③固有性だけ**である。

- **②整合／不整合（F-012）は未実装。**「性格特性と興味が一致しているか／ずれているか」を6ペアで見る層で、掛け合わせの核にあたる。実装していないのは、`docs/processing-design.md` §10-2 が「友人サンプル（n=10〜20）で相関の符号が再現しなければ②層を落とす」と定めており、そのデータがまだ無いため。判定の閾値も未定
- **相手の称号名の表示（F-021）も未実装。**v1のコードが称号IDを運ばないため
- **バッジ（F-020）も未実装**

したがって、**上位2領域に手仕事・挑戦が入らない人は、連携しても結果の見た目が変わらない**。約4割強の人にしか変化が出ない計算になる（8領域から2つを選ぶため）。ボタンの文言でここを過大に約束しないほうがよい。
