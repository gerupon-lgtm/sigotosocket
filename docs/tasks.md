## MVP（第1リリース）

### T-001 プロジェクト初期化
- **完了条件**: 新規リポジトリに `app/`（`index.html`・`css/`・`js/{config,data,domain,infrastructure,presentation}`）と `scripts/`・`docs/`・`tests/` が存在し、`npm test` `npm run dev` が動く。GitHub Actionsで `app/` をGitHub Pagesへ配置できる
- **検証方法**: `npm test` が0件でも成功する／ローカルで `#/` が表示される／Actionsが緑になり、Pages URLで表示される／Cloudflareでサブドメインを向けた状態でHTTPSアクセスできる
- **対応**: 非機能（運用・デプロイ）

### T-002 版数管理（F-009）
- **完了条件**: `app/js/config/app-meta.js` に `appVersion`（`v0.1.0`）・`storageSchemaVersion`・`itemSetVersion`・`scoringVersion`・`typeRuleVersion`・`characterManifestVersion`・`cardTemplateVersion` を定義。フッターに `appVersion` を表示。`npm run version:check` が全反映先の同値を検証する
- **増分規則**: MINOR更新時はPATCHを0、MAJOR更新時はMINOR/PATCHを0へ戻す。正典は `app-meta.js`
- **検証方法**: `app-meta.js` の値を1つずらすと `version:check` が失敗する／フッターの表示が `app-meta.js` と一致する
- **対応**: F-009、非機能（運用）

### T-003 項目マスタのビルド（F-001の前提・正確性）
- **完了条件**: `ORVIS短縮版45問_選定リスト.csv` から `npm run items:build` で `app/js/data/item-master.js` を生成する。**手書きしない**。並び順は**原版の項目番号昇順**（シャッフルなし）。`npm run items:check` が件数45・尺度別内訳（5/4/6/6/4/7/6/7）・itemId重複なし・textJa空なし・負荷量の値域・**順序が項目番号昇順であること**を検証する
- **検証方法**: CSVの1行を削って `items:check` が失敗する／生成物をgit管理し、再生成しても差分が出ない（決定的生成）／ローカライズ済み3項目に `localized: true` が付く
- **対応**: 非機能（正確性・準拠基準）

### T-004 尺度マスタとタイプID（F-004の前提）
- **完了条件**: `scale-definitions.js`（8件・正準順）と `type-definitions.js` のID28件が存在する。IDは `type-<a>--<b>` の正準順。名前・説明は T-019 で埋める
- **検証方法**: 28件が `C(8,2)` と一致する／ID生成が正準順であることのテスト／同じ2尺度から順序を変えて呼んでも同一IDが返る
- **対応**: F-004

### T-005 localStorage 基盤（F-002）
- **完了条件**: キー `sigotosocket:v1` の envelope 読み書き。`schemaVersion` 不一致は読み捨てず保持し、移行不能を表示する。書込失敗（容量超過・プライベートモード）時はメモリ動作へフォールバックし、その旨を表示する。全削除操作を提供する
- **検証方法**: `localStorage` を投げるスタブで例外が外へ漏れない／`schemaVersion: 999` の envelope を置いてもデータが消えない／全削除後に初回状態へ戻る／保存直後にリロードして回答が復元される
- **対応**: F-002、非機能（セキュリティ）

### T-006 ルーティングと画面骨格
- **完了条件**: `#/start`・`#/answer`・`#/result`・`#/card`・`#/about` のハッシュルーティング。未知のルートは `#/start` へ。**問番号をURLに持たない**（ココロパレア踏襲）
- **検証方法**: GitHub Pages上で各URLを直接開いて404にならない／ブラウザの戻るで前画面へ戻る／未知のハッシュが `#/start` へ正規化される
- **対応**: 全画面

### T-007 S-001 トップ（F-002・F-008・F-009）
- **完了条件**: 所要時間「約5分・45問」を明示。保存データがあるときのみ「続きから」「前回の結果を見る」を出す。**ビッグファイブの有無を聞かない**。免責要約と `#/about` 導線、フッターに版数

- **対応**: F-002、F-008、F-009

### T-008 S-002 設問画面（F-001・F-002）
- **完了条件**: 45問を**1問1画面**で出題。5件法。進捗は `n / 45問`。「戻る」は1問目でのみ無効。回答のたびに保存。**出題順は原版の項目番号昇順で固定**
- **検証方法**: 45問目の回答で `#/result` へ／途中でリロードして同じ問・同じ回答が復元される／1問目で「戻る」が無効／375px幅で設問文と選択肢が読める／選択肢のタップ領域が44×44px以上／**出題順が毎回同一であることのテスト**（隣接する2問が同じ尺度にならないことも検証）
- **対応**: F-001、F-002、非機能（対応端末）

### T-009 採点・個人内標準化（F-003）
- **完了条件**: `processing-design.md` §1〜§3 のとおり。**母集団標準偏差（÷8）**。`sd < 1e-9` を判定不能とし、ゼロ除算を起こさない。同値は正準順で安定ソート
- **検証方法**: 全項目1・全項目5・全尺度同値で `standardizable = false` になり例外が出ない／既知の入力に対する z の期待値テスト／同値入力で順位が毎回同じ／標本SD（÷7）に変えるとテストが落ちる（実装固定の確認）
- **対応**: F-003、非機能（正確性）

### T-010 タイプ判定・僅差（F-004）
- **完了条件**: 上位2尺度から `typeId`。`|z[rank1] - z[rank2]| < 0.15` のとき `alternativeTypeId` を設定。判定不能時は `null`
- **検証方法**: 2位と3位が完全同値で代替タイプが出る／1位と2位を入れ替えても `typeId` が変わらない／閾値の境界値（0.1499 / 0.1501）の挙動／判定不能時に例外が出ない
- **対応**: F-004

### T-011 8尺度レーダー（F-005）
- **完了条件**: 正準順で固定の八角形レーダー。回転させない。判定不能時は素点でレーダーのみ描画する
- **検証方法**: 尺度の並びが `scale-definitions.js` の `order` と一致／375px幅でラベルが重ならない／canvas未対応時にテキストの数値一覧へフォールバックする
- **対応**: F-005

- **対応**: F-008

### T-015 キャラクターアセット（F-019）
- **完了条件**: ハリネズミのポーズ8種＋小物8点。1024×1024、**背景透過（アルファ付き）**、文字・カード色を焼き込まない。`character-manifest.js` を `npm run character:manifest` で生成（sha256 integrity 付き）。altテキストを全件に持たせる
- **画風**【想定】: `assets-reference/` のスタイル参照画像は**素案**。精密な色鉛筆・図鑑風・中央に全身1体という方向性のみ確定。**小物の点数と構成は着手前に本人が決定する**
- **制作ルール**: 職業そのものを描かない（道具と所作に変換）／体格・針と尺度の優劣を結び付けない／**丸まった防御姿勢を使わない**（常に開いた姿勢）／猫との対立関係を連想させる配置を使わない
- **検証方法**: `npm run character:check` で全16点の存在・寸法・ハッシュ一致を検証／**全アセットにアルファチャンネルがあり四隅が透明であること**を機械的に検証（白背景のまま書き出す事故を防ぐ）／manifestに欠番がない／altが空でない／判定不能時に使う中立ポーズが用意されている
- **対応**: F-019

- **検証方法**: 生成画像の縦横比が原寸と一致／画像の遅延読込失敗時にエラーを握りつぶさずテキスト結果へ戻す／`toBlob()` が null を返すケースの処理／28タイプ×代表パターンで文字がはみ出さない

- **対応**: 非機能（日時）
