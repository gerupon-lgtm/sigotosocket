# 連携・外部インターフェース設計 — シゴトソケット

サーバーAPIを持たない。実行時の外部連携はココロパレアから受け取るURLフラグメントだけ。ローカルLLMは不採用として記録する。

T-044の回答完了確認と、見直し中の「回答を完了する」はシゴトソケット内の画面状態と既存 `localStorage` だけで完結し、URL・連携コード・外部インターフェースは変更しない。完了確認中・見直し中にココロパレアへ回答や進捗を送らない。

T-045の回答画面・ヘッダー変更と途中回答の破棄もブラウザ内だけで完結する。破棄時を含め、回答値、進捗、履歴を外部へ送らず、ココロパレア連携コードの形式も変更しない。

T-046の回答中ヘッダー統一は表示だけの変更であり、URL、連携コード、保存・共有・外部通信の契約を変更しない。

## 1. ココロパレアとの連携（F-010・第2フェーズ）

サブドメインを分けるため**別オリジン**になる。`localStorage` の直接共有はできない。

### 1-1. 受け渡し方式

ココロパレアの結果画面に遷移ボタンを置き、URLフラグメントで渡す。

```
https://<シゴトソケット>/#b5=v1-342288401195267
```

- **フラグメント（`#` 以降）はサーバーへ送信されない**。通信経路にもアクセスログにも得点が残らない
- 受け取り後、`history.replaceState` でフラグメントを除去する（共有時に得点が漏れない）

### 1-2. 結果コードの仕様（確定）

| 部位 | 内容 |
|---|---|
| 版数 | `v1-` |
| 本体 | 5因子 × 3桁 ＝ 15桁。内部平均（1.00〜5.00）を小数第2位で四捨五入し100倍（100〜500） |
| 因子順 | `intellectImagination` → `conscientiousness` → `extraversion` → `agreeableness` → `emotionalStability`（固定） |

例 `v1-342288401195267` = 3.42 / 2.88 / 4.01 / 1.95 / 2.67

**称号IDは載せない（2026-09-05 本人決定）。** v1のコードは5因子だけを運ぶ。
載せれば相互表示（F-021）でココロパレアの称号名を出せるが、あちらの称号IDは
`conscientiousness-high--extraversion-high` のように長く、生で入れるとコードが一気に伸びる。
短くするには51称号を2桁のIDへ写す対応表が**両リポジトリに**必要で、その表自体が合意事項になる。
版数プレフィックスがあるので、必要になったときに **v2 として追加できる**。受け取り側は
未知の版を無視するよう作ってあるので、v2のコードが古いアプリへ来ても壊れない。

### 1-3. 検証

受け取り側は次を検証し、1つでも満たさなければ**無視して単体結果を表示する**（エラーを見せない）。

- 版数プレフィックスが既知のもの
- 本体が15桁の数字
- 各3桁が 100〜500 の範囲内

### 1-4. ココロパレア側の改修（T-032・別プロジェクト）

- 50問詳細結果だけに「シゴトソケットへ結果を渡す」ボタンを追加し、v1結果コードを生成する
- `location.href` で同じタブを遷移し、組み立て失敗時は結果画面に残して知らせる
- 実装・公開済み。F-023（ORVIS結果の相互表示）は今回の改修に含めず、現行未実装

### 1-5. 受け取り後の保存と画面状態（T-043）

- `bigFive` はlocalStorage内の**単一スロット**であり、複数の結果を同時に保持しない
- 新しい正常なコードを受け取ると、以前の `bigFive` を置き換える。ココロパレア側の履歴は変更・削除しない
- ORVIS結果がある場合は最新の `ResultSnapshot.bigFive` も同じ値へ差し替え、再回答なしで掛け合わせ結果を見られる
- ORVIS結果が無い場合は `bigFive` だけを保存し、45問を完了した時点で新しい結果へ結び付ける
- URLは受け取り後に `#/start` へ正準化し、トップで受領または更新を表示する。この表示はメモリ上の一時状態で、保存形式は増やさない
- 不正コードは従来どおり無視し、受領完了を表示しない

### 1-6. シゴトソケットからの案内リンク

トップと未連携結果に、既定で閉じた連携方法を置く。リンクは同じタブで開く。通常の姉妹アプリ紹介には `appMeta.brand.siblingUrl`（トップURL）を使い、連携方法パネルには `appMeta.brand.siblingLinkageUrl`（`https://kokoro.sikumilab.com/#/sigotosocket`）を使う。専用入口では50問詳細履歴があれば選択一覧、無ければココロパレアのトップが表示される。

## 2. ローカルLLM（F-007・不採用）

**T-031で実装しないと決定した。**`appMeta.llmEndpoint` は `null` のままとし、結果文を含めてLLMへの送信は行わない。以下は検討時の契約案であり、現行実装では使っていない。将来この判断を変更する場合は、要件と決定ログを改訂してから契約を確定し直す。

| 項目 | 内容 |
|---|---|
| 送るもの | アプリ側で組み立て済みの結果文（プレーンテキスト） |
| 送らないもの | 回答値、尺度得点、z値、識別子、日時、その他一切の個人情報 |
| タイムアウト | 3秒【想定】 |
| 失敗時 | 組み立て済みの文をそのまま表示する。利用者にエラーを見せない |
| 出力検証 | 元の文にあった尺度名・タイプ名がすべて残っていること。欠落なら破棄して元の文を使う |
| エンドポイント | 環境変数相当の設定値。未設定なら推敲機能そのものを無効化する |

### 2-1. 検討時のエラーコード案（現行では未使用）

| コード | 内部の意味 | 画面の扱い |
|---|---|---|
| `LLM_DISABLED` | エンドポイント未設定 | 表示しない（機能なしとして動く） |
| `LLM_TIMEOUT` | 3秒超過 | 表示しない。元の文を出す |
| `LLM_UNREACHABLE` | 接続不可 | 表示しない。元の文を出す |
| `LLM_VALIDATION_FAILED` | 出力から尺度名・タイプ名が欠落 | 表示しない。元の文を出す |

いずれも**利用者にはエラーを見せない**。推敲は品質の上乗せであり、必須の依存ではない。開発時のみコンソールへ記録する。

### 2-2. 検討時の冪等性案（現行では未使用）

推敲は副作用を持たない。同じ入力で何度呼んでも安全。失敗時の自動リトライは1回まで【想定】。

## 3. その他の通信

- 実行時の外部送信は行わない。解析タグ、フォントCDN、エラー収集サービス、LLM通信を入れない
- ココロパレアから受け取るのはURLフラグメント内の5因子だけで、回答値は受け取らない
- テストで、自オリジン以外への通信・外部リソース読み込みがないことを確認する
